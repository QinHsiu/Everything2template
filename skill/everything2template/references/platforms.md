# Platform style reference

## Positioning matrix

| Platform | Reader posture | Length | Hook | Trust device | CTA |
|----------|----------------|--------|------|--------------|-----|
| WeChat | Long-stay private/public feed | 1.2–2.8k chars | Scene / tension | Structure + concrete steps | 在看 / 关注 |
| Xiaohongshu | Fast scroll discovery | 0.2–0.7k | Keyword-front title | Steps + before/after | Comment prompt + #tags |
| Zhihu | Search + discussion | 1–2.5k | Conclusion first | Evidence + boundaries | Invite counterexamples |

## Anti-patterns

- Same Markdown pasted to three platforms
- Fake personal experience ("我用了 30 天…") when source has none
- Keyword stuffing / 绝对化违禁用语
- Walls of code without a reader takeaway

## Code / project sources

When CIR comes from `code` or `project`:

1. Lead with the problem the repo solves
2. Show one minimal path: install → run → result
3. Honest tradeoffs (what it does *not* do)
4. WeChat: tutorial narrative; XHS: 3–5 checklist; Zhihu: design rationale + limits

## URL / PDF / DOCX

- Prefer primary claims near the top of CIR `key_points`
- Mark paywall / incomplete extraction in `risks`
- Never "complete" missing sections with guesses
