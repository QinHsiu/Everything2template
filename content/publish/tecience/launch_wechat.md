你是不是也遇到过这种夜晚：

白天刚写完一篇技术长文，晚上却要再「翻译」成公众号、小红书、知乎。改到第三遍，内容开始漂移——数字记不清了，观点变软了，结构却还像同一篇粘贴。

问题通常不在「不会写」，而在**换平台等于换作业题**。

## 学界其实早就在说：结构比裸生成重要

我用 OpenAlex 扫了一圈和「LLM + 改写 / Prompt」相关的工作（检索记录在仓库 `content/publish/tecience/source_brief.md`）。能稳妥写进文里的，只有几条不夸张的共识：

1. **Prompt 与链式结构**能显著提升可控性（经典如 Pre-train, Prompt, and Predict；AI Chains 把人机协作拆成可观察的链）。
2. **信息抽取 / 查询改写**说明：先把材料整理成中间表示，再生成，比端到端「一句话出全文」更不容易胡说。
3. 对创作者而言，落地痛点不是「再调用一次大模型」，而是**多平台各自的阅读契约**——公众号要钩子与小节，小红书要共鸣与收藏步骤，知乎要结论与边界。

所以我做了一个很「土」但好用的选择：**本地优先的转换技能 Everything2template**。

## 它具体干什么

1. **万物摄入**：URL / PDF / DOCX / Markdown / 文本 / 代码 / 项目树  
2. **CIR**：抽成可核验的中间表示（标题、要点、事实边界）  
3. **平台重建**：微信 / 小红书 / 知乎 / 微博 / 抖音 —— 结构不同，不是换皮  
4. **门禁**：套话、长度、CTA 等基础检查  
5. **导出**：Markdown、公众号 HTML、PDF（有中文字体时）

本地试用台一条命令：

```bash
pip install -e .
e2t web
```

浏览器里粘材料，直接看「能不能发出去」。

可选接 DeepSeek / Ollama 做精修；没 Key 时规则引擎仍会按平台模板重写，不会退化成空骨架。
