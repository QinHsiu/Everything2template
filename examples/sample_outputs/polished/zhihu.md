# 如何把网页、PDF、代码项目变成公众号/小红书/知乎可发布草稿？

**先说结论：** 真正可规模化的做法不是「同文换皮」，而是先把异构材料收敛成 CIR（Canonical Intermediate Representation），再按平台结构重建，并配套校验与导出。

## 背景 / 问题定义

创作者与团队常见痛点有三类：

1. 源材料形态多：网页、PDF、文档、代码、项目树
2. 平台语风差：公众号、小红书、知乎对长度、钩子、可信度装置要求不同
3. 交付物弱：只有聊天框里的文本，缺少 Markdown/PDF 存档

市场上不缺云端改写器和矩阵发布套件；缺的是**本地、可被任意 Agent 调用**的适配层。

## 关键论证 1：先 CIR，后平台

若每个平台各自从原文开写，事实点容易漂移。CIR 的作用是「抽取一次、适配多次」：标题、摘要、要点、风险、代码片段先固化，再进入平台模板。这样改写只动结构与语风，不擅自发明数据。

## 关键论证 2：平台要重建，不是换皮肤

- 公众号：场景钩子 + 小节 + 文末互动
- 小红书：关键词前置标题 + 清单 + 标签
- 知乎：结论先行 + 证据/观点分离 + 边界条件

用同一篇长文硬套三个壳，读者和推荐机制都能感知到「假」。

## 反例或边界条件

- 扫描版 PDF 无文字层时，没有 OCR 就无法诚实抽取，应停止并换源
- 自动登录发布会带来账号风险，不应塞进开源核心默认能力
- 本方法提升的是适配效率与一致性，不保证阅读量

## 总结

可执行建议：

1. 用 CLI/Skill 摄入材料生成 CIR
2. 按三平台模板重写并跑质量门禁
3. 导出 MD/PDF 再人工精修 10–20 分钟
